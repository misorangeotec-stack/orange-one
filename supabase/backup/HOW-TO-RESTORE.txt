ORANGE ONE - WHAT IS IN THIS BACKUP, AND HOW TO GET THINGS BACK
================================================================

This folder is filled automatically every night at about 3:00 AM (India time)
by the Orange One portal (orangeonehub.com). Nobody needs to do anything for it
to run. If a night fails, an email is sent to the alert address.


WHAT IS HERE
------------

Orange One Hub/
  Files/            Every document ever uploaded in the portal, arranged as
                      Module / Step / Month / Record / file
                    e.g. Order to Dispatch / 1. Sales invoice / 2026-09 /
                         SO-2627-0047 - NILKANTH PRINT / SINO_4.pdf
                    Files are NEVER deleted from here, even if deleted in the
                    portal. If a file was replaced in the portal, both versions
                    are here ("name (updated 2026-10-02).pdf").
  Files index.csv   One line per file: where it is here, and where it lives in
                    the portal. Opens in Excel. Needed to put files back.
  Database/         A complete copy of the portal's database, one per night,
                    the newest 7 kept. Each is LOCKED (encrypted) - see below.

Tally (ConnectWave)/
  Database/         A complete copy of the Tally mirror database, taken every
                    Sunday, the newest 4 kept. Also locked.

Run logs/           One short note per night: what was copied, and any problem.


LOOKING FOR ONE DOCUMENT (anyone with access can do this)
---------------------------------------------------------

Open Files, then the module, the step, the month, and the record number.
Or type the order / request / PO number into Google Drive's search box.
Nothing needs to be unlocked for this: the documents are ordinary files.


THE DATABASE COPIES ARE LOCKED ON PURPOSE
-----------------------------------------

They contain every user's login, salaries, CVs and customers' commercial terms,
so they are encrypted before they leave the server. They can only be opened with
the DECRYPTION KEY - a small text file starting "AGE-SECRET-KEY-". That key is
NOT kept in Google Drive. It is held by the people named by Orange O Tec.
Without it the database copies cannot be opened by anyone, including us.
Keep at least two copies of the key in two safe places.


RESTORING (technical - for the person rebuilding the system)
------------------------------------------------------------

Tools: age (https://age-encryption.org), PostgreSQL 17 client tools
(pg_restore), rclone.

1. Unlock a database copy:
     age --decrypt -i BACKUP-DECRYPTION-KEY.txt -o orange-one-hub.dump orange-one-hub_YYYY-MM-DD_HHMM.dump.age

2. Restore it into a NEW, EMPTY Supabase project (never over the live one).
   The copy holds the schemas public, private, auth, storage, cron and
   supabase_migrations. In a fresh Supabase project, auth and storage already
   exist, so restore them as data only:
     pg_restore --dbname "<new project connection string>" --no-owner --schema=public --schema=private orange-one-hub.dump
     pg_restore --dbname "<new project connection string>" --no-owner --data-only --disable-triggers --schema=auth --schema=storage orange-one-hub.dump
   One table on its own (the common case: rows deleted by mistake):
     pg_restore --list orange-one-hub.dump | grep <table>
     pg_restore --dbname "<target>" --data-only --table=<table> orange-one-hub.dump
   The cron schema holds the scheduled jobs (emails, reports). Restore it only
   on purpose, after checking where each job would send.

3. Put the files back: "Files index.csv" lists, for every file here, the
   bucket and path it must go back to ("App bucket", "App path"). Copy each
   file to that bucket and path in the new project's Storage.

Rehearse this on a scratch project before relying on it. A backup that has
never been restored is only a hope.
